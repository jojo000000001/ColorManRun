# 跑酷小游戏开发计划

> 项目：ColorManRun  
> 文档日期：2026-10-24  
> 文档性质：后续开发与验收依据，尚未实施的事项不代表已经完成。  
> 输入约束：空格即时普通跳；↑ 短按松开普通跳、长按触发长跳；鼠标左键切换颜色。不得擅自替换为 Shift 长跳或其他变色按键。

## 1. 项目目标与范围

使用当前 Unity 工程制作一个双关卡循环跑酷 Demo：角色自动前进，通过普通跳跃、长距离跳跃和变色越过不连续跑道。

核心规则：

1. 从跑道缝隙掉落，游戏失败。
2. 角色获得地面支撑时，若角色颜色与支撑跑道颜色不一致，立即失败。
3. 到达终点，当前关卡通关。
4. 第一关通关后进入第二关，第二关通关后回到第一关，依次循环。

必需功能：

- 使用 UGUI 实现计时、暂停及必要的结果提示。
- 每关至少四个不连续的长条平台。
- 两个具有实际布局与操作节奏差异的关卡。
- 空格、↑、鼠标左键控制跳跃和变色。
- 接入素材中的 `run`、`jump_start`、`jump_holding`、`change_color`。
- 背景音乐、素材天空盒、使用 Shader 显示的底部镜面效果。
- 输出并验证 Windows 独立运行版本。

本阶段不做程序化无限跑道、横向移动、第三种颜色、复杂存档或 Steam 平台功能。“循环”指有限关卡重复切换，不是无限生成场景。

## 2. 当前工程基线

以下结论来自 2026-10-24 的只读检查，开始实施时应再次核实：

- Unity 版本：`2022.3.62f3c1`。
- 当前配置为 Built-in 渲染管线；本阶段沿用，不同时开发 URP 版本。
- 已有 UGUI 和 TMP 依赖；TMP 字体与所需资源是否齐全仍需验证。
- 当前使用旧输入系统，保留现有方案，不为本 Demo 默认切换至 Both。
- 已有角色 Prefab、橙色/粉色材质、跑道 Prefab 和天空盒资源。
- FBX 已有四个要求的动作切片；实际骨架、播放效果和剪辑时长需要预览确认。
- 角色 Prefab 的 Animator 尚未绑定控制器，尚未看到用于运动的碰撞组件。
- 已有跑道 Prefab 的碰撞尺寸约为 `4.8 × 2 × 56`，局部原点在长条起点附近，不是居中 Cube。
- 本次资源检查未找到 BGM，需要补充来源与授权清晰的音乐。
- 当前参考附件为封面图和原开发计划，未收到可播放的视频。不能据此认定已还原参考游戏的手感或镜面细节。

开发原则：优先检查、验证和复用已有资源，不重复新建工程，不直接覆盖现有角色或跑道素材。

## 3. 开发原则

1. 先冻结规则，再完成技术验证和灰盒闭环。
2. 先确定角色实际跳跃能力，再设计平台长度、缺口和颜色节奏。
3. 提前验证镜面可行性，不把首次尝试留到开发末尾。
4. 玩法逻辑驱动动画，动画不决定角色是否完成跳跃、落地或变色。
5. 胜负、暂停和切关由统一状态控制，所有入口使用同一套重置流程。
6. 每完成一个阶段就验证，不把测试全部压到最后。
7. 平台数量和装饰可以缩减，硬性要求与独立构建测试不能删减。

## 4. 操作与输入契约

### 4.1 固定操作

- 自动前进：游戏处于 Playing 时无需按键，角色沿跑道方向移动。
- 空格：按下当帧提交普通跳请求，不等待松开。
- ↑ 短按：按住不足长按阈值，松开当帧提交普通跳请求。
- ↑ 长按：达到长按阈值时提交长跳请求，不等待松开。
- 鼠标左键：切换橙色与粉色，逻辑颜色立即生效。
- 暂停：UGUI 暂停按钮为必需入口；Esc 暂停/继续属于可选快捷键，不改变上述玩法操作。

首版不额外引入 Shift 长跳、C 变色、数字键直选颜色等替代操作。

### 4.2 ↑ 按压状态

每次 ↑ 按压独立记录“正在蓄力”和“本次按压已消耗”：

1. 按下时，若处于 Playing 且角色仍有地面或土狼时间起跳资格，开始蓄力。
2. 蓄力期间角色继续前进；不减速，不自动悬停。
3. 未达到阈值就松开：提交一次普通跳请求，结束本次按压。
4. 达到阈值：提交一次长跳请求，并将本次按压标记为已消耗。
5. 已达到阈值的按压，松开时不得再次提交普通跳。
6. 长跳请求即使因失去起跳资格而未执行，本次按压也不得持续重试或自动连跳。
7. 初始不支持在空中开始蓄力；在空中按下 ↑ 的这次按压忽略，松开后才能重新开始。

长按阈值初始为 `0.2s`，按 Playing 中的游戏时间累计。它会改变起跳位置，属于需要复核关卡的参数，不只是手感参数。

### 4.3 起跳资格与重复输入

- 已落地或处于有效土狼时间内，可以接受一次起跳。
- 起跳成功后立即消耗资格，不允许空中二段跳。
- 空格和 ↑ 的短按普通跳请求可以使用短时输入缓冲；过期即丢弃。
- ↑ 长跳在到达阈值时尝试一次，不长时间排队等待下一次落地。
- 同一帧最多执行一次起跳；空格即时请求优先于同帧 ↑ 请求。
- ↑ 蓄力期间若空格起跳成功，消费本次 ↑ 按压，后续松开不得补跳。
- 按住任一跳跃键跨过落地，不得自动重复跳跃，除非另行修改规则并重跑验收。

### 4.4 变色与 UI 隔离

- 首版仅使用橙色、粉色两种逻辑颜色。
- 鼠标左键只在 Playing 且本次点击未归 UI 消费时提交变色请求。
- 初始冷却为 `0.35s`；冷却内点击丢弃，不排队补执行。
- 点击暂停、继续、重试按钮不得同时触发变色，包括恢复 Playing 的同一次点击。
- UI 使用统一输入归属规则；指针是否位于 UI 上是辅助判断，不是唯一防线。
- 明确按钮键盘提交行为，避免空格同时跳跃和触发已选中的 UI 按钮。
- 跳跃与变色同帧执行时，先处理可执行的起跳，再更新颜色，最后依据实际运动后的支撑状态判定颜色。
- 只有真正离开支撑后才按悬空处理，不能通过重复跳跃请求绕过地面颜色判定。

### 4.5 暂停与状态变化

进入暂停、死亡、通关、切关或重试时，清空蓄力、输入缓冲及未处理的操作请求。

恢复或进入新关卡时：

- 如果跳跃键仍被按住，等待松开后再接受这次键的新按压。
- 不将恢复界面的鼠标点击穿透给玩法。
- 不保留暂停前未完成的 ↑ 蓄力。
- 暂停期间不累计冷却与蓄力时间。

## 5. 运动与碰撞方案

首版采用 CharacterController 承担角色移动与碰撞，逻辑层维护前进速度、垂直速度和重力。

约束：

- 角色运动不依赖直接修改 Transform 再用单根射线补救。
- 不混用两套同时驱动角色位置的运动系统。
- 角色模型作为视觉子物体，关闭 Root Motion。
- 地面探测用于确认有效支撑及所属长条，不替代角色碰撞系统。
- 起跳与上升过程中不能提前吸附地面。
- 对碰撞体尺寸、边缘支撑、台阶跨越等行为进行实测，避免自动跨过应当掉落的缺口。
- 侧面接触不算落地，不触发支撑颜色比较。
- 镜面平面仅渲染，不带碰撞，也不参与地面检测。
- 终点触发体与角色运动方案必须在技术验证阶段测试，不能只凭“有碰撞体”就认定会触发。
- 基础跟随相机在灰盒阶段接入，便于判断起跳时机；最终平滑与构图后调。

落地、失败和终点事件必须幂等，同一结果不能重复结算。

## 6. 颜色与胜负判定

### 6.1 逻辑颜色

使用统一的颜色 ID 定义角色和跑道颜色。材质只负责显示，不通过材质名称或 RGB 浮点值推断规则。

- 橙色和粉色对应现有角色及跑道材质。
- 角色只切换需要变色的部分，保留原有白色等非变色区域。
- 黑色跑道资源不自动成为第三种玩法颜色。是否作为装饰或其他用途，必须显式配置。
- 出生颜色必须与起始平台一致。

### 6.2 判定时机

- 实际获得有效支撑时，检查角色与支撑长条的颜色。
- 保持地面支撑时，变色后立即重新检查。
- 空中变色不与下方远处跑道比较，不提前判死。
- 接触多个候选平台边缘时，应按确定的支撑选择规则判定，避免帧间抖动。
- 失去支撑后持续受重力影响，低于死亡高度判为掉落失败。
- 终点放在最后安全平台内部，不能让角色从终点外侧或下方误通关。
- 同一帧同时满足死亡和终点条件时，死亡优先；结果只结算一次。

## 7. 跳跃参数与关卡计算

### 7.1 初始参考值

- 前进速度：`8m/s`。
- 重力加速度大小：`35m/s²`。
- 普通跳初始垂直速度：`8.5m/s`。
- 长跳初始垂直速度：`11.5m/s`。
- 长跳水平速度倍率：`1.45`，仅在该次长跳腾空阶段生效，落地后恢复。
- 土狼时间：`0.08s`。
- 普通跳输入缓冲：`0.1s`。
- ↑ 长按阈值：`0.2s`。
- 变色冷却：`0.35s`。
- 死亡高度初值：角色逻辑根节点 `y < -8m`，与平台顶面和镜面高度一并核对。

这些是调试起点，不是已验证的最终参数。

### 7.2 理论值与适用边界

同高度起落、连续运动、恒定重力且无碰撞干扰时：

- 滞空时间：`T = 2 × 起跳垂直速度 / 重力大小`。
- 水平位移：`D = 前进速度 × T × 本次跳跃倍率`。

上述初值对应：

- 普通跳约 `0.486s`，水平位移约 `3.89m`。
- 长跳约 `0.657s`，水平位移约 `7.62m`。
- 若仅按理论位移的 80% 初筛，分别约 `3.11m` 和 `6.10m`。

不能把理论水平位移直接当成缺口宽度。设计还需容纳：

> 缺口宽度 + 起跳退让距离 + 落地安全距离 ≤ 实测可用跳跃位移。

原计划长跳缺口上限 `6.5m` 已超过其 80% 理论余量，因此不得不经实测直接沿用。

### 7.3 ↑ 蓄力对布局的影响

前进速度为 `8m/s` 时，蓄力 `0.2s` 会继续前进约 `1.6m`。

每个长跳缺口必须同时预留：

1. 玩家看到前方缺口和颜色的观察距离。
2. 长按输入达到阈值所需的前进距离。
3. 可稳定起跳的安全窗口。
4. 空中变色与落地后的恢复距离。

不能把土狼时间当成常规的蓄力补偿。应让正常长跳在离开平台前完成蓄力并触发。

### 7.4 调参顺序

1. 调整前进速度和重力，确定整体节奏。
2. 调整两种跳的初速和长跳倍率，实测起落轨迹。
3. 调整土狼时间、输入缓冲、长按阈值与变色冷却。
4. 根据最终行为确定缺口、平台长度和颜色节奏。
5. 每个平台连接记录安全起跳窗口，验证不是只有极限一帧才能通过。
6. 最后依据实际滞空和剪辑时长调动画。

以上任一相关参数改变，都要重新检查已有关卡的可解性。

提高前进速度会增加同条件下的理论跳距，同时减少观察和反应时间，不应笼统记作“跳距安全余量变小”。

“必须长跳”的缺口需实测普通跳在土狼时间、边缘支撑等宽容条件下仍不能通过。

## 8. 两关设计

### 8.1 共用结构

每关一个 LevelRoot，包含出生点、平台容器和终点。共用角色、相机、UI、音频和状态管理器。

- 首版可用启用/禁用关卡根节点切换，不要求切换场景。
- 两关可以复用空间坐标，但同一时刻只能有当前关卡参与玩法碰撞。
- 平台统一顶面高度、起终点定义与长度配置方式。
- 禁止在不了解既有 Prefab 原点和尺寸的情况下套用居中 Cube 摆放公式。
- 先保证每关四个平台，再视时间增加到六个平台和七个平台。

### 8.2 第一关：逐步教学

- 起始安全段，给予观察和熟悉自动前进的时间。
- 普通跳缺口。
- 跳跃中完成一次变色的连接。
- 预留充分蓄力距离的长跳缺口。
- 安全终点段。

若四个平台不足以清楚承载上述教学节奏，应增加平台，不强行堆叠操作。

### 8.3 第二关：组合运用

- 使用不同的平台长度与缺口顺序。
- 加入普通跳、长跳、空中变色的组合。
- 可设置两个必须长跳的缺口，但要逐一验证输入窗口。
- 缩短恢复段时仍要满足蓄力和变色冷却要求。
- 不依赖收窄跑道体现玩法难度：固定中心线且无横向移动时，收窄通常只是视觉变化。
- 不以“复制第一关只改颜色”作为最终目标。

每个连接点需要记录：前后平台颜色、长度、缺口、建议跳法、↑ 开始蓄力区域、起跳窗口、落点及试玩结果。

## 9. 状态、计时与重置

### 9.1 运行状态

- Ready：准备开始，不响应正式玩法。
- Playing：角色运动、接收输入、累计单关时间。
- Paused：暂停运动、玩法输入和计时，UI 可操作。
- Dead：冻结本次用时，显示死因，等待重试。
- Clear：冻结本次用时，显示通关提示。
- Transitioning：屏蔽玩法输入，执行关卡切换和统一重置。

Clear 的提示初定显示一秒真实时间后进入下一关。明确 UI 用时和玩法用时不同，不依赖暂停后的游戏时间推进提示。

### 9.2 单关计时

- 首版显示本次单关用时。
- 仅 Playing 时累加游戏时间。
- 暂停冻结，继续接着累计。
- 死亡和通关后定格。
- 重试当前关和进入下一关时清零。
- 最佳成绩、整轮累计时间属于后续可选项。

### 9.3 统一重置清单

重试与切关必须走同一套基础重置流程，至少处理：

- 当前关卡启用状态、角色出生位置和出生颜色。
- 前进速度、垂直速度、支撑平台与起跳资格。
- ↑ 蓄力、按压消费标记、土狼时间、输入缓冲和变色冷却。
- Animator 参数、触发器及视觉状态。
- 单关计时、死因、结果面板和按钮交互状态。
- 相机位置、前视目标和相机平滑速度。
- 时间倍率、音频暂停状态及重复播放保护。
- 上一轮通关、死亡或重试遗留的延迟任务。

使用可取消任务或回合版本号等办法，保证上一轮“一秒后切关”不能影响已经重试的新一轮。

## 10. 动画

- 沿用素材适配的骨架类型，先预览，不因“Generic 更稳”而盲目修改导入设置。
- 跑步使用 `run`，起跳使用 `jump_start`，空中使用 `jump_holding`，变色使用 `change_color`。
- `run` 和 `jump_holding` 循环；另外两个按一次性动作处理。
- 运动状态决定基础动画，逻辑位移不由动画事件驱动。
- 起跳动作在实际起跳后立即可见。
- 起跳退出时机根据剪辑时长、播放速度和实际滞空调整，不预先写死 Exit Time。
- `jump_holding` 当前切片很短，需预览确认是否能稳定表现空中姿态。
- 落地可以立即打断空中动作；死亡可以打断其他动作。
- 变色结束后返回当前实际运动状态，不固定返回 Run。
- 可按素材适配性选择独立层/遮罩或短全身动作；两种方案都不能中断逻辑运动。
- 没有死亡素材时不强制新增死亡动画，可用已有姿态和简单失败反馈。

## 11. UGUI 与音频

### 11.1 必需 UI

- HUD：单关用时、当前关卡、暂停按钮。
- 操作提示：空格普通跳；↑ 短按松开普通跳、长按长跳；左键变色。
- 暂停面板：继续、重开当前关。
- 失败面板：区分掉落和颜色不匹配，提供重试。
- 通关提示：显示完成与下一关信息。

要求：

- 不同分辨率下关键信息不被裁切。
- 暂停时按钮和必要 UI 动效仍可使用。
- 按钮事件不重复注册；可采用 Inspector 绑定或代码绑定，不将某一种方式本身当成验收要求。
- 恢复、重开和切关不会遗留暂停状态。
- 可选：失去窗口焦点时自动暂停，恢复焦点不自动开始奔跑。

### 11.2 音频

- BGM 循环播放，暂停时同步暂停。
- 明确音乐、音效及可选 UI 音效的暂停策略。
- 切关和重试不创建重复播放的 BGM。
- 跳跃、变色、落地、失败音效为可选增强，不挤占核心功能和测试时间。
- 记录音乐来源及许可；计划 Steam 发行时必须确认商用和分发授权。

## 12. 天空盒与镜面

### 12.1 提前验证

正式制作前，用当前 Built-in 管线验证：

- 水平平面能够显示一个动态物体和天空盒的正确倒影。
- 相机移动、俯仰变化后倒影仍保持合理位置和方向。
- 镜面自身不参与反射，不产生递归渲染。
- 平面以下不需要出现的物体可以正确裁剪。

验证失败时先调整实现方案与估时，不继续假设完整镜面可以在最后两小时直接完成。

### 12.2 首版实现范围

- 单个水平镜面，使用反射相机、RenderTexture 和地面 Shader。
- 正确处理反射视图、剔除方向、镜面裁剪、投影采样及纹理方向。
- 反射更新与主相机渲染顺序一致，避免明显滞后一帧。
- 初始优先低分辨率反射纹理，根据目标机器性能调整。
- 限制反射对象与阴影开销，不包含镜面自身及不必要内容。
- 不加入景深、复杂扭曲或多层反射；Fresnel 是效果增强项。
- 反射相机不带多余 AudioListener。
- 明确反射纹理和相机的创建、释放及重置策略。

镜面高度可从跑道下方约两米开始调试，但不是不可更改的定值。必须保证不影响玩法碰撞、掉落可读性和画面构图。

验收依据是倒影位置、方向、遮挡、动态表现和性能，不是“材质面板能看到矩阵”。

## 13. 推荐排期

目标为三天、合计二十四小时，包含三小时缓冲。以下为估算，不是已经验证的交付保证；资源或镜面技术验证失败时需重新估时。

### 第一天：八小时

1. 资源检查与规则冻结：一小时。
2. 技术验证：两小时。重点验证角色碰撞、↑ 输入边界、终点触发和基础镜面。
3. 灰盒玩法闭环：五小时。完成自动跑、两种跳、变色、两种死亡、终点、重试、基础暂停和基础相机。

出口条件：一条测试路线可以稳定反复完成“开始—操作—失败或通关—重开”。

### 第二天：七小时开发与一小时缓冲

4. 两关设计与循环：三小时。每关先满足四个平台，实测缺口和蓄力窗口，完成连续切关与重置。
5. 动画、UGUI 与音频：四小时。完成全部必需动作、界面和 BGM。
6. 当日缓冲：一小时。

出口条件：所有必需玩法和表现能连续演示，关卡顺序为第一关、第二关、第一关、第二关。

### 第三天：六小时开发与两小时缓冲

7. 天空盒、镜面与视觉整合：三小时。基于第一天验证结果完善，不更换管线。
8. Windows 构建与回归：三小时。验证输入、暂停、切关、重试、分辨率与性能。
9. 最终缓冲：两小时。

出口条件：Windows 独立版本通过必需项与边界回归，可以交付演示。

原计划的里程碑合计为十五小时，第一天阶段合计九小时，与“每天八小时”的描述不一致。单人排期不将“理论可并行”作为实际节省。

### 时间不足时的缩减顺序

1. 最佳成绩、相机震动、闪屏等增强项。
2. 额外音效与非必要 UI 动效。
3. 镜面的 Fresnel、扭曲和高分辨率，保留真实镜面基础效果。
4. 平台数量降至每关至少四个，保留两关的实质布局差异。
5. 复杂动画分层，改用已验证的简单方案，仍保留四个指定动作。

不得删减：掉缝失败、颜色失败、两种跳跃、固定输入、两关循环、四个指定动画、暂停计时、BGM、天空盒、镜面及独立构建验证。

## 14. 验收清单

### 14.1 需求验收

- [ ] UGUI 显示时间和暂停入口。
- [ ] 每关至少四个不连续平台。
- [ ] 两关有实质布局或操作节奏差异。
- [ ] 连续通关顺序为第一关、第二关、第一关、第二关。
- [ ] 掉缝能够判定失败。
- [ ] 异色落地能够判定失败。
- [ ] 空格按下立即普通跳。
- [ ] ↑ 短按在松开时普通跳。
- [ ] ↑ 长按达到阈值自动长跳，松开不补跳。
- [ ] 左键切换橙色和粉色。
- [ ] `run`、`jump_start`、`jump_holding`、`change_color` 均可观察到。
- [ ] BGM 正常循环，暂停与恢复正常。
- [ ] 天空盒来自现有素材。
- [ ] 底部通过 Shader 显示正确的动态镜面。
- [ ] Windows 独立构建可以运行。

### 14.2 输入边界

- [ ] ↑ 蓄力接近平台边缘时，触发时机和失败行为符合规则。
- [ ] ↑ 长按跨过落地，不会自动连续跳跃。
- [ ] ↑ 蓄力期间按空格，不会出现后续额外跳跃。
- [ ] 空格与 ↑ 同帧触发时最多起跳一次，优先级一致。
- [ ] 空中按 ↑ 不开始新的蓄力；普通跳缓冲过期后不补执行。
- [ ] 起跳和变色同帧的结果可重复，不依赖脚本偶然执行顺序。
- [ ] 暂停时仍按着跳跃键，恢复后不会误起跳。
- [ ] 点击暂停、继续、重试不会同时变色。
- [ ] 空格不会误触仍处于选中状态的 UI 按钮。
- [ ] 冷却期间的变色点击不会延后补执行。

### 14.3 碰撞与判定

- [ ] 低帧率下不穿过平台，不错误吸附地面。
- [ ] 普通跳、长跳在不同帧率下的可达范围基本一致。
- [ ] 平台边缘的支撑、土狼时间和落地行为稳定。
- [ ] 侧面接触平台不会被当成正确落地。
- [ ] 空中变色不提前判死，异色落地不漏判。
- [ ] 地面直接变错颜色立即失败。
- [ ] 必须长跳的缺口不能用普通跳和宽容参数绕过。
- [ ] 终点不能从侧面或下方误触发通关。
- [ ] 死亡与终点同帧发生时，只产生死亡结果。
- [ ] 镜面平面不承接角色，不阻止掉落失败。

### 14.4 状态与交付

- [ ] 空中暂停后继续，角色、动画与计时正常。
- [ ] 暂停界面重开，不遗留时间倍率和音频暂停状态。
- [ ] 连续通关至少十次，无颜色、速度、相机或动画残留。
- [ ] 连续重试至少十次，无重复 BGM、重复按钮回调或旧切关任务。
- [ ] 反射方向、位置、遮挡正确，没有递归反射。
- [ ] 多分辨率下 UI 可用，操作提示清晰。
- [ ] 在记录硬件、分辨率及图形设置的 Windows 构建中测性能。
- [ ] 目标稳定 60 FPS；不能只以编辑器瞬时表现认定达标。
- [ ] 无阻断运行的错误，并记录剩余已知问题。

## 15. 建议职责划分

以下是职责建议，不要求为了对应清单而建立过多脚本：

- GameManager：状态、关卡索引、胜负结算、统一重置与延迟任务管理。
- PlayerInput：空格、↑、左键的输入语义及消费规则，可先作为控制器内部模块。
- PlayerController：运动、跳跃、重力、地面支撑与起跳资格。
- PlayerColorPalette：沿用已有材质引用，按需补充颜色显示接口，不重复维护另一套颜色源。
- TrackPart：平台逻辑颜色、长度和平台标识。
- FinishTrigger：报告终点接触，由状态管理器决定是否通关。
- PlayerAnimation：根据实际运动和变色事件更新动画，可按复杂度决定是否独立。
- HudController：界面显示和按钮事件，不直接改写角色物理状态。
- CameraFollow：基础跟随、前视和重置。
- PlanarMirror：反射相机、纹理和材质参数生命周期。

现有资源路径优先保留；新增内容按需归档，不因目录整洁而批量移动已引用资源。

## 16. Steam 发行后续阶段

本计划交付玩法 Demo，不等于 Steam 可发行版本。后续单独评估：

- 角色、天空盒、音乐等素材的商用及分发许可。
- 自有游戏名称、商店素材和视觉表达，避免直接复用参考游戏品牌。
- 操作设置、音量、显示设置、退出流程和必要的本地保存。
- 兼容性、异常退出、安装与更新验证。
- Steam 发行资料、构建与审核流程。
- 成就、云存档、手柄和本地化等按实际产品需要增加的功能。

在上述 Demo 通过验收前，不提前引入平台 SDK 或与核心玩法无关的大型系统。
